# Explainer-страница: ментальная модель с анимацией механизма

Один самодостаточный HTML-файл: текстовые блоки модели плюс пошаговые плееры там, где есть движение или смена состояния. Без библиотек, без сети, без 3D. Движок плеера фиксирован в `assets/explainer-template.html`; заполняется только объект `EXPLAINER`.

## Когда строить страницу

- Пользователь просит «покажи», «с анимацией», «оживи», «сделай страницу/лендинг», «визуализируй».
- Тема описывает процесс: протокол, pipeline, цикл, обмен сообщениями, автомат состояний, алгоритм по шагам.

Не строить, если механизм статичен (определение, классификация, сравнение свойств): там достаточно текста и таблицы. Анимация только там, где движение показывает причину.

## Пайплайн

1. **Сначала текстовая модель** по правилам скилла. Страница не заменяет её, а переводит в другую форму.
2. **Таблица сцен в чате до кода.** Одна строка на шаг:

   | шаг | кто активен | что движется (от → к, подпись) | что изменилось (узел: состояние) | утверждение | источник |

   Пользователь видит таблицу и может поправить до генерации. Одно утверждение на шаг. Если строк больше 12, разбить на два плеера.
3. **Сущности = узлы.** 3–7 узлов, каждый с `id`, именем и ролью. Узел на карте равен понятию из несущей системы модели. Не добавлять узлы «для полноты», которых нет в тексте.
4. **Заполнить `EXPLAINER`** в копии шаблона: скопировать `assets/explainer-template.html` в рабочую папку как `<slug>-explainer.html`, заменить объект между `const EXPLAINER = {` и `};`. Движок ниже не трогать.
5. **Проверить**: `node -e` на синтаксис объекта; открыть файл в браузере, если есть возможность; проверить, что каждый `from`/`to` в пакетах и каждый ключ в `states` существует в `nodes`.
6. **Отдать маршрут просмотра**: какой блок открыть первым, на каком шаге остановиться, что заметить. Перечислить шаги с пометкой `assumption: true`.

## Какие блоки модели становятся плеерами

| Элемент модели | Форма на странице |
|---|---|
| Проблема, зачем | Текстовый блок |
| Несущая мысль | Поле `core` в шапке |
| Причинный механизм, сквозной пример | Плеер: пакеты между узлами, крупный план, состояние узлов накапливается |
| Формализм, формулы, код | Текстовый блок с `<pre>`; формула привязана к шагу плеера словами |
| Разные интерпретации одного принципа | Один плеер с теми же шагами и перелабеленными узлами, или таблица «контекст, вход, операция, выход, что неизменно» |
| Границы, что ломается | Плеер из 2–4 шагов «параметр изменён → что перестало работать», или текст, если показать нечего |
| Проверка понимания | Блок `recall`: та же карта с пустыми узлами и вопросы с скрытыми ответами |

## Правила честности

- **Сначала истина, потом картинка.** Реальные имена полей, порядок шагов и числа берутся из источника до написания сцен. Поле `source` в шапке обязательно.
- **`because` на шаге** указывает, откуда утверждение. Если источника нет, ставить `assumption: true`: шаг получит серую метку «допущение» прямо в плеере.
- **Никаких выдуманных чисел.** Если точное значение неизвестно, писать «например, 100» в тексте шага и не ставить число в подпись пакета как факт.
- **Движение только для причинности.** Пакет летит, потому что что-то реально передаётся. Подсветка узла означает, что он действует. Эффекты «для красоты» не добавлять.
- **Состояние накапливается.** `states` на шаге описывает только изменение; плеер сам показывает итоговое состояние на любом шаге.
- **Reduced-motion** даёт статичные кадры без потери смысла: текст шага должен быть понятен и без движения.

## Схема объекта `EXPLAINER`

```js
{
  title, subtitle, core, source,
  nodes: [{ id, label, sub, icon, col, row, color }],   // color: cyan | purple | orange | green | pink
  links: [[fromId, toId]],
  sections: [
    { id, kicker, title, html },
    { id, kicker, title, html, player: { example, steps: [STEP] } },
    { id, kicker, title, html, recall: { questions: [{ q, a }] } }
  ]
}
STEP = { title, text, active: [id], packets: [{ from, to, label, kind }], states: { id: 'состояние' },
         focus: '<html>', phase: 'Виток 2', because: 'источник', assumption: false }
// kind: ctx | ok | call | err | data
```

`focus` принимает произвольный HTML крупного плана; элементы с классом `rv` появляются по очереди. Готовые классы: `note`, `note warn`, `note good`, `pre`, `table`.

## Управление в плеере

Назад / Далее, Авто с паузой, сброс, скраббер, точки шагов, стрелки клавиатуры. `seek(шаг, прогресс)` детерминирован: одинаковый вход даёт одинаковую картинку, поэтому страницу можно снимать покадрово для видео без переделки.
